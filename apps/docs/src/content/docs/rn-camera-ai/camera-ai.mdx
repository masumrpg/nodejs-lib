The `<CameraAI />` component is the central hardware preview and vision coordinator in `@masumdev/rn-camera-ai`. It wraps React Native Vision Camera v5 (Nitro) hardware capture, handles camera runtime permissions, runs AI frame processors off the JavaScript thread, and displays bounding box overlays.

```tsx
import { CameraAI } from '@masumdev/rn-camera-ai';
```

---

## Component API Reference

```tsx
<CameraAI
  processor={myProcessor}
  cameraPosition="back"
  resizeMode="cover"
  isActive={true}
  fps={15}
  onDetections={(detections) => console.log(detections)}
  onError={(error) => console.error(error)}
  style={styles.camera}
/>
```

## Resize Modes: `cover` vs `contain`

Camera sensors typically capture video in standard 4:3 or 16:9 sensor aspect ratios (e.g., $1920 \times 1080$, $1280 \times 720$), while modern smartphones have elongated screen aspect ratios (19.5:9, 20:9, etc.).

`CameraAI` supports two distinct scaling modes, matching the standard CSS/React Native image resizing models:

```
┌──────────────────────────────────────┐     ┌──────────────────────────────────────┐
│             cover Mode               │     │            contain Mode              │
│                                      │     │  ┌────────────────────────────────┐  │
│ ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐  │     │  │       Pillarbox Letterbox      │  │
│ │                                 │  │     │  ├────────────────────────────────┤  │
│ │     Video preview scales up     │  │     │  │                                │  │
│ │     to fill container.          │  │     │  │    Entire stream is visible    │  │
│ │     Excess edges are cropped.   │  │     │  │    without cropping.           │  │
│ │                                 │  │     │  │                                │  │
│ └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘  │     │  ├────────────────────────────────┤  │
│                                      │     │  │       Pillarbox Letterbox      │  │
│                                      │     │  └────────────────────────────────┘  │
└──────────────────────────────────────┘     └──────────────────────────────────────┘
```

### 1. `cover` (Default)
- **Visual Behavior**: The stream scales up until both width and height completely cover the container. Any portion of the stream that exceeds the container boundaries is cropped symmetrically.
- **Offsets**: `offsetX <= 0` and `offsetY <= 0`.
- **Use Case**: Fullscreen camera views, immersive AR experiences, and standard photo/video capturing viewports.

### 2. `contain`
- **Visual Behavior**: The stream scales down until the entire frame fits completely inside the container, preserving the stream's full field of view. Black letterbox (top/bottom) or pillarbox (left/right) margins are introduced if aspect ratios differ.
- **Offsets**: `offsetX >= 0` and `offsetY >= 0`.
- **Use Case**: Document scanning, bar code inspection where edge-to-edge frame visibility is critical, or embedded camera widgets.

## Permission Handling & Fallbacks

`<CameraAI />` automatically inspects camera permission status on mount using Vision Camera's `useCameraPermission()`.

- If permission is not yet determined, `requestPermission()` is called automatically.
- If permission is denied by the user, `<CameraAI />` displays the `permissionFallback` view and invokes `onError` with code `'PERMISSION_DENIED'`.

### Custom Permission Fallback

You can supply a completely custom component for the denied state via the `permissionFallback` prop:

```tsx
import { CameraAI } from '@masumdev/rn-camera-ai';
import { View, Text, TouchableOpacity, Linking, StyleSheet } from 'react-native';

export function MyCameraView() {
  return (
    <CameraAI
      processor={myProcessor}
      permissionFallback={
        <View style={styles.permissionDenied}>
          <Text style={styles.title}>Camera Access Required</Text>
          <Text style={styles.subtitle}>
            Please grant camera permissions in system settings to use real-time detection.
          </Text>
          <TouchableOpacity
            style={styles.button}
            onPress={() => Linking.openSettings()}
          >
            <Text style={styles.buttonText}>Open Settings</Text>
          </TouchableOpacity>
        </View>
      }
    />
  );
}

const styles = StyleSheet.create({
  permissionDenied: {
    flex: 1,
    justifyContent: 'center',
    alignItems: 'center',
    backgroundColor: '#111827',
    padding: 24,
  },
  title: { color: '#f9fafb', fontSize: 20, fontWeight: '700', marginBottom: 8 },
  subtitle: { color: '#9ca3af', fontSize: 14, textAlign: 'center', marginBottom: 24 },
  button: { backgroundColor: '#3da441', paddingHorizontal: 20, paddingVertical: 12, borderRadius: 8 },
  buttonText: { color: '#ffffff', fontWeight: '600' },
});
```

## Lifecycle Management (`isActive`)

Mobile cameras and neural network inference consume significant battery and GPU/NPU resources. Use the `isActive` prop to cleanly pause and resume operations:

- **Screen Blur / Navigation**: In React Navigation or Expo Router, pass `isActive={isFocused}` so camera capture halts when users navigate to another screen.
- **App Backgrounding**: When the application enters the background, set `isActive={false}` to release hardware capture sessions and avoid Android OS battery warnings.
- **Modal Sheets**: Pause detection while showing a confirmation dialog or action sheet over the camera.

```tsx
import { useIsFocused } from '@react-navigation/native';
import { CameraAI } from '@masumdev/rn-camera-ai';

export function Screen() {
  const isFocused = useIsFocused();

  return (
    <CameraAI
      processor={detector}
      isActive={isFocused}
    />
  );
}
```

## Error Handling Hierarchy

All errors emitted by `CameraAI` inherit from `CameraAIError`:

```typescript
export class CameraAIError extends Error {
  readonly code: string;
  readonly cause?: unknown;
}

// Emitted for permission denial or missing hardware sensors
export class CameraError extends CameraAIError {}

// Emitted for invalid model paths, Corrupted weights, or delegate failures
export class ModelLoadError extends CameraAIError {}

// Emitted during frame processing or tensor execution failures
export class InferenceError extends CameraAIError {}
```

### Catching and Responding to Errors

```tsx
<CameraAI
  processor={detector}
  onError={(err) => {
    switch (err.code) {
      case 'PERMISSION_DENIED':
        console.warn('User refused camera permissions');
        break;
      case 'CAMERA_UNAVAILABLE':
        console.warn('Physical camera sensor is missing or busy');
        break;
      case 'INFERENCE_ERROR':
      case 'INFERENCE_FAILED':
      case 'PROCESSOR_INIT_FAILED':
        console.error('Frame processing or initialization failed:', err.cause);
        break;
      default:
        console.error('Unexpected camera AI error:', err);
    }
  }}
/>
```

## Declarative Overlay & 468-Point Face Mesh Customization

`<CameraAI />` provides a 3-layer customization architecture for bounding boxes, label badges, and 468-point 3D Face Mesh wireframes without requiring manual coordinate math:

### 1. Declarative `overlayTheme` & `boxVariant`

Switch between `'solid'`, `'corners'` (4-corner scanner brackets), and `'dashed'` bounding boxes, or hide the box entirely (`showBoxes: false`) while customizing every anatomical region of the 468-point Face Mesh:

```tsx
<CameraAI
  processor={faceRecognizer}
  cameraPosition="front"
  overlayTheme={{
    showBoxes: true,
    boxVariant: 'corners',
    boxColor: '#10b981',
    unrecognizedBoxColor: '#38bdf8',
    cornerLength: 24,
    cornerThickness: 3,
    labelPosition: 'top-left',
    formatLabel: (det) =>
      det.identity?.isRecognized
        ? `${det.identity.name} (${Math.round(det.identity.similarity * 100)}%)`
        : det.label,
    meshStyle: {
      showMeshLines: true,
      showTesselation: true,
      showDots: true,
      dotRadius: 1.8,
      eyeDotRadius: 2.5,
      lineThickness: 1.0,
      eyeContourColor: '#22d3ee',
      lipOuterContourColor: '#34d399',
      faceOvalColor: 'rgba(56, 189, 248, 0.75)',
      tesselationColor: 'rgba(56, 189, 248, 0.38)',
    },
  }}
/>
```

### 2. Custom Per-Element Render Slots (`renderBox`, `renderLabel`, `renderLandmarkDot`)

If you want to render your own React Native components for individual boxes, labels, or landmark dots, `<CameraAI />` automatically computes the cover/contain scaling and front-camera mirroring and passes screen-ready pixel coordinates (`pixelBox` / `point`):

```tsx
<CameraAI
  processor={faceRecognizer}
  renderBox={({ detection, pixelBox, color }) => (
    <View
      style={{
        position: 'absolute',
        left: pixelBox.x,
        top: pixelBox.y,
        width: pixelBox.width,
        height: pixelBox.height,
        borderWidth: 2,
        borderColor: color,
        borderRadius: 16,
      }}
    />
  )}
  renderLandmarkDot={({ point, color, radius }) => (
    <View
      style={{
        position: 'absolute',
        left: point.x - radius,
        top: point.y - radius,
        width: radius * 2,
        height: radius * 2,
        backgroundColor: color,
      }}
    />
  )}
/>
```

### 3. Full-Canvas Custom Overlay (`renderOverlay`)

While `<CameraAI />` includes a built-in `<DetectionOverlay />` component, you can also take over the entire overlay canvas using the `renderOverlay` prop:

```tsx
import { CameraAI, type DetectionResult, type ViewDimensions } from '@masumdev/rn-camera-ai';
import { View, Text, StyleSheet } from 'react-native';

export function CustomOverlayCamera() {
  const renderCustomOverlay = (
    detections: DetectionResult[],
    viewDimensions: ViewDimensions
  ) => {
    return (
      <View style={StyleSheet.absoluteFill} pointerEvents="none">
        {detections.map((det) => {
          // Calculate pixel position
          const x = det.boundingBox.x * viewDimensions.width;
          const y = det.boundingBox.y * viewDimensions.height;
          const width = det.boundingBox.width * viewDimensions.width;
          const height = det.boundingBox.height * viewDimensions.height;

          return (
            <View
              key={det.id}
              style={[
                styles.customBox,
                { left: x, top: y, width, height }
              ]}
            >
              <View style={styles.badge}>
                <Text style={styles.badgeText}>
                  {det.label.toUpperCase()} ({Math.round(det.confidence * 100)}%)
                </Text>
              </View>
            </View>
          );
        })}
      </View>
    );
  };

  return (
    <CameraAI
      processor={myProcessor}
      renderOverlay={renderCustomOverlay}
    />
  );
}

const styles = StyleSheet.create({
  customBox: {
    position: 'absolute',
    borderWidth: 2,
    borderColor: '#38bdf8',
    borderRadius: 8,
  },
  badge: {
    backgroundColor: '#38bdf8',
    paddingHorizontal: 6,
    paddingVertical: 2,
    alignSelf: 'flex-start',
    borderTopLeftRadius: 6,
    borderBottomRightRadius: 6,
  },
  badgeText: {
    color: '#0f172a',
    fontSize: 11,
    fontWeight: '700',
  },
});
```

## Smart Document Capture, `<DocumentGuideOverlay />` & `<ScannerAnimationOverlay />`

For paper-fitting capture scanners, combine `documentGuide` (with `<DocumentGuideOverlay />` animating all 4 independent corner vertices and rotated edge arms smoothly via Reanimated 4 GPU transforms, including tilted/trapezoid quads via `guide.corners: DocumentQuad`) and capture-triggered `<ScannerAnimationOverlay scanRegion={...} />`:

- **Declarative Theming**: Customize every state color (`searchingColor`, `adjustingColor`, `optimalColor`, `analyzingColor`, `completeColor`), corner stroke/radius (`cornerLength`, `cornerThickness`, `cornerRadius`), outer mask (`showMask`, `maskColor`), status badge position (`'top' | 'bottom'`), and laser bar via `documentGuideTheme` and `scanAnimation`.
- **Full Custom Headless UI**: Override any piece individually via `renderDocumentGuide`, `renderDocumentCorner`, `renderDocumentStatus`, `renderDocumentCenter`, `renderAnimationOverlay`, `renderLaser`, or `renderStatusBadge`.

```tsx
import React, { useRef, useState } from 'react';
import {
  CameraAI,
  type CameraAIRef,
  type CapturedPhotoResult,
  type DocumentGuideTarget,
} from '@masumdev/rn-camera-ai';

export function DocumentCaptureCamera() {
  const cameraRef = useRef<CameraAIRef | null>(null);
  const [captured, setCaptured] = useState<CapturedPhotoResult | null>(null);
  const [guide, setGuide] = useState<DocumentGuideTarget>({
    box: { x: 0.08, y: 0.14, width: 0.84, height: 0.64 },
    readiness: 'searching',
    optimalityScore: 0,
    statusText: 'Arahkan kertas ke dalam sudut bingkai',
  });

  const captureStill = async () => {
    const photo = await cameraRef.current?.capturePhoto({
      flashMode: 'off',
      enableShutterSound: false,
    });
    if (photo) {
      setCaptured(photo);
    }
  };

  return (
    <CameraAI
      ref={cameraRef}
      processor={alignmentProcessor}
      enablePhotoCapture={true}
      showBoxes={false}
      showLabels={false}
      showLandmarks={false}
      isActive={!captured}
      documentGuide={guide}
      documentGuideTheme={{
        cornerLength: 28,
        cornerRadius: 14,
        optimalColor: '#22c55e',
        adjustingColor: '#f59e0b',
      }}
      scanAnimation={false}
    />
  );
}
```

`<ScannerAnimationOverlay />` runs entirely on the Reanimated 4 UI thread (`transform` + `opacity` only), uses zero-bounce quint/cubic curves (`Easing.bezier(0.23, 1, 0.32, 1)` & `Easing.bezier(0.77, 0, 0.175, 1)`), and automatically degrades to stationary corner reticles when OS `ReduceMotion.System` is enabled.

## Design System Theme Token Binding (Optional)

`@masumdev/rn-camera-ai` includes a neutral, optional theme token binding layer designed to dynamically harmonize camera HUD chrome, bounding boxes, face meshes, document reticles, and fallback cards with your application's active design system (e.g. `@masumdev/rn-ui`):

### 1. Local Binding with `theme` Prop

Pass color tokens directly to any `<CameraAI />` component:

```tsx
import { CameraAI } from '@masumdev/rn-camera-ai';
import { useTheme } from '@masumdev/rn-ui';

export function Screen() {
  const { theme } = useTheme();

  return (
    <CameraAI
      processor={myDetector}
      theme={theme.colors} // Binds primary, warning, success, info, surface, border
    />
  );
}
```

### 2. Global Provider Architecture (`CameraAIThemeProvider`)

Wrap your root layout with `<CameraAIThemeProvider>` to cascade tokens across all camera views:

```tsx
import React, { useMemo } from 'react';
import {
  CameraAIThemeProvider,
  createCameraAIThemeFromTokens,
} from '@masumdev/rn-camera-ai';
import { ThemeProvider, useTheme } from '@masumdev/rn-ui';

function CameraBridge({ children }: { children: React.ReactNode }) {
  const { theme } = useTheme();
  const cameraTheme = useMemo(
    () => createCameraAIThemeFromTokens(theme.colors),
    [theme.colors]
  );

  return (
    <CameraAIThemeProvider theme={cameraTheme}>
      {children}
    </CameraAIThemeProvider>
  );
}

export default function RootLayout() {
  return (
    <ThemeProvider defaultThemeName="cyber">
      <CameraBridge>
        <AppNavigator />
      </CameraBridge>
    </ThemeProvider>
  );
}
```
